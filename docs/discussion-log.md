## 2026-10-01 15:48 — 需求讨论（四）：按系统的入口名与会话文件

恩公把整体模型复述成一段完整的使用过程，并补了三处具体设定：

- **入口按系统命名**：打开 Terminal 运行 `python muse_macos.py`
  （或 `muse_win11.py`、`muse_ubuntu.py`），文件名代表不同系统——
  云端因此知道他在哪台系统上，下发的命令可以针对该系统，不会
  发错（比如把 dir 发给 Mac）。此条取代 15:35 的 `local_muse.py`。
- **一次运行 = 一个会话 = 一个 JSON 文件**：运行脚本后，这个
  Terminal 窗口就开始记录，对应一个 `日期-系统名.json`；记录的
  内容包括恩公本人的输入输出，也包括云端命令的输入输出，直到
  会话结束。（助手注：记录终端屏幕流即可，sudo 密码不回显、
  天然不入账，与 15:40 红线一致。）
- **退出命令**：输入一个特殊命令（例如 `macos(exit)`），客户端
  结束，终端退回原本的 shell。

助手留了一条待细化：系统名不等于机器名（M1 与 M3 Air 都是
macos），网关任务终究是发给具体机器的，机器身份怎么定（多半是
脚本自动识别或启动参数），设计阶段处理。文件内部结构、同日
多次会话的命名，同样留到设计阶段。

## 2026-10-01 15:40 — 需求讨论（三）：去掉输入框，普通 terminal 模型

恩公把客户端形态进一步简化，取代了 15:35/15:37 两版：

- **不用输入框，就像普通 terminal**：客户端是一段普通终端会话；
  云端命令在里面顺序执行，输出直接打在终端上。客户端"释放光标"
  （命令与命令之间），键盘就归恩公，他可以照常用这个终端。
- **sudo 的处理**：命令照常先执行，停留在输入密码的地方，他输入
  密码就继续。不再有"预填输入框、回车执行"的特殊流程，也不需要
  协议层的 `needs_root` 标记和人工待办槽。
- **终止权**：任何命令执行的时候，他随时可以 Ctrl+C 终止过程。

助手当场点明的两条边界（记入 DESIGN 待设计落实）：

1. sudo 有几分钟的免密窗口：他输过一次密码后，短时间内再来的
   sudo 命令不会再停、会直接跑过去——"卡住等他"不是每次都在。
   云端下达要紧的权限命令时，在对话里先告知他的规矩（15:15）
   不变，正好补上这个缺口。
2. 用户在终端敲入的内容（尤其密码）一字不进 JSON 记录，列为红线。

已同步标注 DESIGN.md §3.1.4、§3.2.4 与 protocol/task-queue.md
（needs_root 改为"已定不采用"）。

## 2026-10-01 15:37 — 需求讨论（二）：权限命令进输入框、回车执行

恩公在三个选项中选了第一个：

- **权限命令直接进输入框，他回车就在客户端里跑。** 即：云端下发的
  特殊权限命令到达后，客户端不自动执行，而是把命令摆进终端下方的
  输入框；恩公看过、回车，命令就在他自己的终端会话里执行——sudo
  当面向他要密码，客户端全程不经手、不记录密码。命令与输出照常
  记进 JSON 记录（人工执行的这条要可辨识，具体标记留到设计阶段）。
- 未选的另外两种（他在别处终端执行后粘回输出、两种都要）不采用；
  以后若改主意再议。

已标注到 DESIGN.md §3.1.4 与 §3.2.4。空闲时输入框的用途（助手理解
为他自己敲命令、一并记录）仍待确认。

## 2026-10-01 15:35 — 需求讨论（一）：分系统做、终端形态、JSON 记录

## 2026-10-01 15:1x — 项目收敛：muse-hands → muse-python

本地控制台（muse-pipe 仓库的 local_client.py + index.html）试验收官，
恩公总结定案：

- **左栏聊天多余**：他在 Muse app 或浏览器里聊天即可，全系统通用；
  控制台网页聊天只留作备选入口，不再投入。
- **右栏记录才是价值**：他要的是"我（云端）下达了什么命令、执行得
  怎么样"的完整记录，不需要他在这边输入。

  他执行后给结果。由此给客户端加了唯一的人工入口——**人工待办槽**：
  权限命令在客户端排队提示，他亲手跑完把输出粘回，结果沿同一通道
  回传，审计不缺页。

结论：muse-hands 收敛为**完全的 Python 项目 muse-python**——纯标准库
客户端，接收命令、回传结果、记录过程，外加人工待办槽。2026-09-30 的
"Hermes 转交执行"降为协议预留（kind=hermes），v1 执行器就是 shell
直执（当天已在 M1 真机实证）。网关 /tasks/* 零改动。仓库是否改名
（Python-muse-hands → muse-python 系）待恩公定；文档先行，代码等
